## 3. Функции, ссылки и копирование

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | `5` и `23` | `5`, `23` | `2 + 3` — сложение чисел. В `"2" + 3` один операнд строка, поэтому `+` выполняет конкатенацию и возвращает строку `"23"`, а не число. |
| 2 | `undefined` | `undefined` (до исправления), `16` (после) | Тело стрелочной функции в фигурных скобках не возвращает значение автоматически. Выражение `value * value;` вычисляется и теряется, а без `return` результат вызова — `undefined`. |
| 3 | `5` и `true` | `5`, `true` | `alias = product` не копирует объект, а копирует ссылку. Обе переменные указывают на один объект, поэтому изменение через `alias` видно через `product`. `const` запрещает только переприсваивание переменной. |
| 4 | `7`, `false`, `true` | `7`, `false`, `true` | `[...products]` создаёт новый массив (`products !== copy`), но элементы в нём те же самые объекты (`products[0] === copy[0]`). Изменение `copy[0].stock` изменило и объект в исходном массиве. Копирование поверхностное. |
| 5 | `3 8 3` и `false` | `3 8 3`, `false` | `{ ...product, stock: 8 }` — последнее свойство перекрывает скопированное, поэтому `first.stock === 8`. В `{ stock: 8, ...product }` порядок обратный: spread идёт последним и возвращает `3`. Верхний объект новый (`product !== first`), исходный не изменился. |
| 6 | `Без названия`, `Без названия`, `null`, пустая строка | `Без названия`, `Без названия`, `null`, пустая строка | Значение по умолчанию подставляется только при пропущенном аргументе или `undefined`. `null` и `""` — переданные значения, поэтому остаются как есть. |

**Исправление эксперимента 2:** причина — отсутствие `return` в теле стрелочной функции с фигурными скобками. До исправления `square(4)` возвращал `undefined`. Вместо `value * value;` записано `return value * value;`, после чего `square(4)` возвращает число `16`. Можно было также убрать фигурные скобки: `(value) => value * value`.

## 4. Модель данных и функции

**Задача** — плоский объект с четырьмя полями:

| Поле | Правило |
|---|---|
| `id` | Положительное безопасное целое число (`Number.isSafeInteger` и `id > 0`). Строки и другие типы не преобразуются. Уникальность проверяется в `addTask`. |
| `title` | Строка. После `trim()` длина от 1 до 100. Хранится очищенная строка, внутренние пробелы сохраняются. |
| `completed` | Логическое значение. При создании всегда `false`. |
| `priority` | Строго `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`. |

**Распределение ответственности между файлами:**

- `src/data.js` — только данные: общий набор `demoTasks`, номер варианта и `variantTasks`.
- `src/task-service.js` — прикладная логика: проверки и девять операций над переданным массивом. Нет `console.log`, нет чтения `demoTasks` и нет глобального списка.
- `src/main.js` — демонстрационные сценарии: импорт, последовательность действий, вывод и обработка отказов.
- `checks.js` — проверочный сценарий на встроенном `node:assert/strict`.

**Результаты операций:**

| Функция | При успехе | При ошибке |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект | `undefined` (задача не найдена) |
| `getPendingTasks` | новый массив невыполненных задач | — |
| `getTaskTitles` | новый массив названий | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask` | `{ ok: true, tasks }`, новая задача в конце | `{ ok: false, error }` (некорректные поля или повторный `id`) |
| `setTaskCompleted` | `{ ok: true, tasks }` | `{ ok: false, error }` (некорректный `id`, не `boolean`, задача не найдена) |
| `renameTask` | `{ ok: true, tasks }` | `{ ok: false, error }` (некорректный `id` или название, задача не найдена) |
| `removeTask` | `{ ok: true, tasks }` без выбранной записи | `{ ok: false, error }` (некорректный `id`, задача не найдена) |

**Почему id не равен индексу:** индекс — текущая позиция элемента в массиве, и она меняется при удалении соседних записей. `id` идентифицирует задачу и остаётся прежним. В `demoTasks` задача с `id = 4` лежит по индексу `1`, а `tasks[4]` вообще не существует. Поэтому задача ищется через `find` по `id`, а не обращением `tasks[id]`.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число можно использовать в дальнейших расчётах и сравнениях, а строка нужна только для отображения. Округление `toFixed(1)` применяется при выводе в `main.js`: функция расчёта не должна терять точность и зависеть от формата показа. Это же позволит использовать её из обработчика на странице.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив (`map`) и новый объект только для изменяемой задачи (`{ ...task, completed }` или `{ ...task, title }`). Остальные объекты переиспользуются по ссылке без изменения. Входной массив и его объекты не мутируются: при успехе и при ошибке они остаются прежними.

## 9. Вывод

В ПР1 расчёты выполнялись над отдельными переменными, а здесь каждая задача стала объектом, список — массивом объектов, а операции над ним — функциями в отдельном модуле. Возвращаемые значения используются везде: функции чтения возвращают объект, массив или сводку, а функции создания и изменения возвращают объект результата `{ ok, ... }`, из-за чего `main.js` решает, как показать данные и ошибки. Неизменность данных проверена сравнением входных массивов и объектов до и после вызова, дополнительно в готовой проверке 33 входные данные заморожены `Object.freeze`, а в сценариях `main.js` сравниваются снимки `demoTasks` и `variantTasks`. Ошибка, которую пришлось исправить: пропущенный `return` в стрелочной функции эксперимента 2, из-за чего `square(4)` возвращал `undefined`.
