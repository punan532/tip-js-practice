## Задание 8 доп Вариант А — данные строками

Файл: js/progress-input.js. Входные значения приходят строками, поэтому перед расчётом их нужно проверить и аккуратно преобразовать.

| Входные строки | Результат |
|---|---|
| "12", "5" | Обычный расчёт: осталось 7, прогресс 41.7%, статус «В работе» |
| "  12  ", " 5 " | После trim() пробелы убираются, результат тот же, что и выше |
| "" | Ошибка: пустой ввод |
| "   " | После trim() строка становится пустой → ошибка: пустой ввод |
| "abc" | Ошибка: значение не является целым числом (Number("abc") даёт NaN) |
| "2.5" | Ошибка: значение не является целым числом (Number даёт 2.5, а не целое) |
| "Infinity" | Ошибка: значение не является целым числом (Number("Infinity") даёт Infinity, отклоняется проверкой Number.isFinite) |
| null | Ошибка: вместо строки передано другое значение (typeof null не равен "string") |
| undefined | Ошибка: вместо строки передано другое значение |

Почему недостаточно просто вызвать Number() и проверить, что результат не отрицателен:
Number() слишком снисходителен и может дать обманчиво "нормальное на вид" число там, где вход на самом деле некорректен. Например, Number("") возвращает 0, а не сигнал ошибки — пустой ввод незаметно превратился бы в ноль задач. Number("Infinity") возвращает Infinity, которое больше нуля и прошло бы проверку "не отрицательно", хотя это не является допустимым количеством задач. Number("2.5") даёт 2.5 — положительное число, но не целое, а количество задач обязано быть целым. Наконец, Number(null) равен 0, а Number(undefined) равен NaN - оба случая нельзя было бы отличить от настоящих нулевых или ошибочных данных без явной проверки типа и пустой строки до вызова Number(). Поэтому нужна отдельная проверка типа, trim() и проверка на целостность и конечность числа, а не одна лишь проверка знака.
